# 数据说明

## 1. 数据任务分层

本项目不把所有文件合并成一个“总测试集”，而是按评测目的拆分为四层。

### 1.1 整段正负混合测试集

每条记录是一段完整回答，同时包含 AI 文本与人工文本。它是计算整体准确率、AI 检出率和人工文本误检率的主测试集。

推荐字段：

| 字段 | 含义 |
|---|---|
| `id` | 样本或原文组标识 |
| `question` | 生成或回答所对应的问题 |
| `answer` | 待检测的整段文本 |
| `label` | 真实标签，`1` 为 AI，`0` 为人工 |
| `source` | 主题或公开数据来源类别 |

### 1.2 分句压力集

将整段回答切分为句子或短片段，用于观察文本变短后检测能力的变化。同一原文的多个句子可共享 `id`。

分句集必须单独报告，不能与整段集直接横向比较。若进行数据切分，同一 `id` 下的全部句子必须进入同一分区，防止原文泄漏。

### 1.3 同题跨生成器压力集

使用同一批唯一问题分别生成多个模型的回答，用于评估检测器对不同生成器的泛化能力。

推荐字段：

| 字段 | 含义 |
|---|---|
| `id` | 问题标识 |
| `question` | 唯一问题 |
| `answer` | 某生成器的完整回答 |
| `label` | 固定为 `1` |
| `generator` | 生成器公开名称或匿名代号 |
| `source` | 主题类别 |
| `target_char_count` | 生成长度目标，可为空 |

这类集合只有正样本，因此只能报告检出率、漏检数、置信度分布和分组结果，不能计算人工文本误检率。

### 1.4 训练候选集

训练或微调候选样本与测试数据物理隔离。它们不参与当前测试指标，且必须先完成按问题、原文、生成批次和近重复文本的组级去重。

## 2. 结果文件

黑盒检测结果统一为：

| 字段 | 含义 |
|---|---|
| `id` | 输入记录标识 |
| `true_label` | 真实标签 |
| `source` | 主题或来源类别 |
| `original_length` | 原始字符数 |
| `sent_length` | 实际送检字符数 |
| `truncated` | 是否截断 |
| `api_label` | 检测器预测标签 |
| `confidence` | 接口返回置信度；不默认解释为 AI 概率 |

公开脚本同时接受 `predicted_label` 作为预测字段名。

## 3. 数据质量门槛

正式测评前至少检查：

1. `id`、真实标签、待测文本是否为空；
2. 标签是否只使用约定值；
3. 同一测试文件中是否存在完全重复或规范化后重复文本；
4. 不同数据分区之间是否共享问题、原文或生成批次；
5. 结果数是否与输入数一致，`id` 是否完整对应；
6. 是否存在超长截断，截断规则在各运行间是否一致；
7. 纯 AI 集是否被错误用于计算误检率；
8. 文件名中的“去重”是否与实际唯一文本数量一致。

## 4. 已淘汰的早期试验集

早期曾构建一个小规模、人工平衡的 200 正样本 / 200 负样本集合。该集合存在规模小、长度范围窄、生成来源较旧、与后续同题跨模型设计不一致等问题，现仅视为流程联调产物：

- 不纳入当前正式指标；
- 不作为 GitHub 示例数据来源；
- 不用于模型选择、阈值调整或优化结论；
- 不在公开材料中声称为“正式测评集”。

## 5. 公开版数据策略

公开仓库只提供合成记录，用于验证脚本格式与计算逻辑。真实文本、真实问题、逐条预测、内部来源字段和可反向定位的数据均不公开。
