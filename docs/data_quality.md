# 数据检查记录（脱敏版）

本页只记录可复用的问题类型，不披露真实文件、样本、接口或指标。

## 1. 文件名不能证明已经去重

检查过程中发现，个别带有“dedup/去重”字样的中间文件仍包含大量重复问题。正式流程因此改为按规范化文本计算哈希，并同时报告：

- 总行数；
- 唯一问题数；
- 唯一回答数；
- 重复行数与重复组数。

同一问题对应人工回答和多个 AI 回答时，问题重复是数据结构的一部分；但生成题库应先提取唯一问题，避免某些问题被重复生成并获得更高权重。

## 2. 句级重复与整段重复含义不同

分句数据中，同一原文 `id` 多次出现是预期行为。拆分训练/验证/测试时必须按原文 `id` 分组，而不能逐句随机切分。

整段跨生成器数据中，完全相同的回答通常不是预期行为，可能来自模板化拒答、生成失败、缓存复用或采集逻辑问题，应先核对再决定保留、降权或删除。

## 3. 空标签必须排除并留痕

只要真实标签或预测标签无法归一化，该行就不能进入混淆矩阵分母。评估脚本在 `skipped_rows` 中记录被排除的 CSV 行号。

当前公开脚本不在报告中保存原始标签值或文本，避免错误信息泄露敏感内容。正式内部流程可在受控环境中另行记录排除原因。

## 4. 纯正类集合的指标边界

跨生成器压力集只包含 AI 文本，适合发现生成器迁移导致的漏检，但不能计算人工文本误检率，也不能单独代表整体准确率。

## 5. 截断是模型条件的一部分

同一原文在不同运行中必须使用一致的最大长度和截断方式。当前公开脚本会保留并识别长度字段，但尚未内置 `truncated=True/False` 分组。

需要截断分析时，可先生成两个独立结果文件分别评估，或按扩展开发章节新增安全的布尔分组维度。

## 6. 训练候选集与测试集隔离

后续新增生成模型的回答首先进入训练候选区，不自动并入正式测试。只有完成问题、原文、生成批次和近重复检查，并明确用途后，才能进入开发集、验证集或新冻结测试集。
